# 项目状态与功能清单

## 当前阶段

当前仓库进入 **v0.3 发布队列阶段**。

目前代码已经覆盖下面这条完整主流程：

```text
创建实例
→ 扫码登录 QQ
→ 持久化登录态
→ 添加频道
→ 创建任务
→ 启动发布队列
→ 顺序读取 pending 任务
→ 打开真实 pd.qq.com 频道页
→ 检查登录状态
→ 写入 ProseMirror 正文
→ 上传视频/图片文件
→ 等待“发表”按钮可用
→ 点击发表
→ 验证发布结果
→ 保存目标状态 / 错误 / 截图
→ 随机等待
→ 下一条任务
```

## 3. Chromium 登录态持久化与登录检测

已实现：

- Electron 内置 Chromium `WebContentsView`。
- 每实例独立 persistent partition。
- 每实例独立加密登录备份。
- 打开 `https://pd.qq.com/`。
- Cookie / LocalStorage / IndexedDB 等浏览器 Profile 持久化。
- 根据真实页面 `.app-login .user-info .name` / `.app-login .user-card .name` 检测已登录账号。
- 顶部“检测登录”。
- 顶部显示“已登录 / 未登录或已失效”。
- 单任务执行前自动检查登录状态。
- 队列运行中遇到登录失效后自动暂停，避免后续任务连续失败。
- 登录失效时将当前未完成任务恢复为 pending，重新登录后可继续。

状态：**v0.3 基础流程已实现，仍需要真实运行持续验证**。

待完善：

## 6. 真实腾讯频道 DOM 适配

用户已经提供登录后的真实 `pd.qq.com` 频道页 HTML。

从真实 DOM 已确认：

```html
<div contenteditable="true" data-exeditor-root class="ProseMirror">...</div>

<div class="image-video-container">
  ...
  <input hidden type="file" multiple
    accept="image/png,image/jpeg,image/jpg,image/webp,image/gif,video/mp4,...">
</div>

<div class="publish-button">
  <button class="g-button g-button--primary g-button--small btn" disabled>
    发表
  </button>
</div>
```

已实现：

- 正文从旧 `textarea` 改为 ProseMirror `contenteditable`。
- 默认正文选择器：`.editor-root-container .ProseMirror[contenteditable="true"]`。
- 默认上传选择器：`.image-video-container input[type="file"]`。
- 默认发表按钮：`.publish-button button:has-text("发表")`。
- 一个元素支持多行候选选择器并自动降级。
- 设置文件后等待“发表”按钮从 disabled 变为 enabled。
- 上传过程中持续检测页面错误提示。
- 点击发表后优先检测成功提示。
- 若没有明确 toast，则使用“编辑器被清空 + 发表按钮重新 disabled”作为备用成功判断。

状态：**核心代码已完成；静态 DOM 适配完成，真实发布结果仍需实机验证**。

## 7. 失败恢复

已实现：

- 单目标失败自动重试。
- 默认最大重试 2 次，可在设置页修改。
- 重试次数保存到 `task_targets.retry_count`。
- 单目标失败不会重复执行已经成功的频道。
- 失败自动截图。
- 截图保存到 Electron `userData/screenshots/YYYYMMDD/`。
- 错误原因和截图路径写入数据库日志。
- GUI 提供“重试失败目标”。
- 登录失效视为特殊错误：暂停队列并保留当前任务，而不是继续把后续任务打成失败。

待完善：

- 按错误类型决定是否重试。
- 网络错误指数退避。
- 页面 HTML 快照。
